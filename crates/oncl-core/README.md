# oncl-core

Rust-библиотека для тех, кто хочет подписывать и проверять файлы из своей программы. Это ядро проекта [OpenNCALayer](https://github.com/arynyklas/OpenNCALayer): подпись, проверка, инспекция и метки времени для файлов и потоков байт. Доверие, ключи, часы, сеть, журнал аудита и лимиты задаёт ваша программа («хост»). В библиотеке нет окон, демона, открытого порта, установщика и самообновления, графическая сессия не нужна.

**Статус: до версии 1.0 (`0.1.0-alpha.*`).** Между альфа-версиями публичный API может ломаться; изменения перечислены в заметках о миграции [`docs/dev/sdk.md`](../../docs/dev/sdk.md). В crates.io крейты не опубликованы, поэтому `cargo add` не подойдёт: подключайте их по git или по path (ниже). Свободны ли имена `oncl-*` в crates.io, не проверялось.

## Как подключить

Из рабочей копии репозитория, на проверенном вами теге или коммите:

```toml
[dependencies]
oncl-core = { path = "OpenNCALayer/crates/oncl-core", features = ["full"] }
oncl-pki = { path = "OpenNCALayer/crates/oncl-pki" }

# SDK использует наши форки `streebog` и `hmac` (в них добавлены варианты с секретным входом).
# Проект вне нашего workspace должен нести тот же патч. `rev` — те же, что в
# `[patch.crates-io]` корневого `Cargo.toml`.
[patch.crates-io]
streebog = { git = "https://github.com/arynyklas/hashes", rev = "7f67647379b26e89068874cfe8cf3bf0c8e72b69" }
hmac = { git = "https://github.com/arynyklas/MACs", rev = "062e38d40e71236dcf49275ab7f9bd491b033c1c" }
```

Или по git, закреплённому на коммите (секция патча та же):

```toml
[dependencies]
oncl-core = { git = "https://github.com/arynyklas/OpenNCALayer", rev = "<коммит>", features = ["full"] }

[patch.crates-io]
streebog = { git = "https://github.com/arynyklas/hashes", rev = "7f67647379b26e89068874cfe8cf3bf0c8e72b69" }
hmac = { git = "https://github.com/arynyklas/MACs", rev = "062e38d40e71236dcf49275ab7f9bd491b033c1c" }
```

## Features

Без features (по умолчанию) это минимальный SDK: CMS/CAdES, хеширование, проверка цепочек сертификатов, ключи из файлов и встроенные ключи PKCS#12 и JKS, ключи с именем от хоста, пакеты операций и инспекция. Остальное включается так:

| feature   | что добавляет                                                              |
|-----------|----------------------------------------------------------------------------|
| `tokens`  | аппаратные токены и удостоверения личности как источники ключей (`oncl-token`) |
| `xml`     | подпись, добавление подписи и проверка XMLDSig, XAdES, WS-Security (`oncl-xml`) |
| `pdf`     | подпись и проверка PAdES (`oncl-pdf`)                                      |
| `jose`    | создание, добавление и проверка JWS и JWT                                  |
| `plugins` | безголовый хост плагинов WebAssembly (включает `xml`)                      |
| `full`    | всё перечисленное; по-прежнему без интерфейса, desktop, обновления, сервера и асинхронного рантайма |

## Примеры

Каждый пример запускается командой `cargo run -p oncl-core --example <имя>`. Они на лету выпускают одноразовую RSA PKI и не ходят в сеть:

- `sign_file [КАТАЛОГ [ФАЙЛ]]` — отсоединённая подпись CMS файла ключом PKCS#12 при строгой проверке; применение ключа записывается журналом хоста (`KeyUseGuard`).
- `verify_file КАТАЛОГ ФАЙЛ` — проверяет такую подпись; завершается ненулевым кодом, если вердикт не `Valid`.
- `custom_transport` — свой `HttpTransport`, подключённый к проверке; без «сети» строгая подпись отклоняется до применения закрытого ключа.

Пример `sdk_probe` старше остальных. Это приёмочная проба, которая сверяет результат с независимыми программами; как руководство по встраиванию он не подходит.

## Главное, что нужно знать

- `Engine` строится из `EngineServices` (службы хоста). Операцию он допускает через `Engine::begin(ExecutionGrant, OperationPolicy, control)`. Права выдаёт доверенный код хоста, а не запрос по сети.
- Закрытый ключ применяется через `KeyUseGuard`. Его `before_use` должен надёжно записать применение **до** использования ключа; если запись не удалась, ключ применять нельзя. Ошибки несут `AppliedState` (`NotApplied`, `Applied`, `Unknown`). SDK не обещает ни отката, ни «ровно одного применения».
- Отчёты проверки раздельно показывают целостность подписи, цепочку до корня, срок действия, отзыв, доказательство метки времени и заявленное время (`Verdict`). Отсутствие доказательств никогда не выдаётся за действительность.
- Лимиты по умолчанию: 1 ГиБ на документ и 1 ГиБ учтённой живой памяти на операцию; документ больше 1 ГиБ отклоняется. Это лимиты учёта, а не измерение RSS.

Полный список лимитов, правила стабильности и версий и готовность к публикации — в [`docs/dev/sdk.md`](../../docs/dev/sdk.md).
