# oncl-server {{VERSION}} ({{FLAVOR}})

`oncl-server` — HTTP-сервис OpenNCALayer: другие программы могут просить его подписать или проверить документ по HTTP. Настольная программа ему не нужна.

По умолчанию сервис ничего не слушает. HTTP API выключен, пока вы не напишете закрытый файл конфигурации и не включите API (`enabled = true` или `serve --enable-api`). Сервис сам не устанавливает сертификаты, не добавляется в автозапуск и не обновляется.

## Быстрый старт

Первый запуск с примером конфигурации ничего не открывает:

```sh
oncl-server --version
oncl-server serve --config /etc/oncl-server/server.toml
# disabled: no listener      <- так и должно быть, пока в конфигурации enabled = false
```

Дальше:

1. Скопируйте `server.example.toml` в закрытый каталог, который доступен только вам. Подробности — в `docs/server.md`.
2. Создайте токен для клиента:

   ```sh
   oncl-server token-create --directory /etc/oncl-server --name client.token
   # печатает verifier=<64 шестнадцатеричных знака>; вставьте его в раздел [[tokens]] файла server.toml
   ```

3. Включите API на локальном адресе: `oncl-server serve --config ... --enable-api`.
4. Подключитесь клиентом `oncl` из отдельного пакета:
   `oncl --endpoint http://127.0.0.1:13579 --token-file client.token ...`

Чтобы сервис был доступен из локальной сети, настройте TLS или доверенный обратный прокси. Сам по себе он такой доступ не открывает.
