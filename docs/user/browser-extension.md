# Расширение браузера

Расширение — самый простой способ подключить OpenNCALayer к сайту. Сертификат и порт 13579 при этом не нужны. Здесь описано, как поставить расширение, как оно работает и чем ограничено.

## Как это работает

Расширение подменяет на странице соединения `WebSocket` к `127.0.0.1`, `localhost` и `[::1]` (порты 13579–13679). Сообщения идут в OpenNCALayer через «native messaging» — встроенный в браузер способ связи с программой:

1. Браузер запускает маленькую программу-посредник `nmhost` (relay).
2. Посредник запускает OpenNCALayer, если тот ещё не работает.

Если посредник не установлен или программа не запускается, расширение отдаёт странице обычный `WebSocket`, то есть оригинальный NCALayer (если он запущен).

## Установка

### 1. Получите файлы расширения

Готовые файлы лежат в [Releases](https://github.com/arynyklas/OpenNCALayer/releases):
- `openncalayer-chromium-<версия>.zip` — для Chrome, Edge, Yandex Browser;
- `openncalayer-firefox-<версия>.xpi` — для Firefox (не подписан, см. ниже).

Можно собрать из исходников:

```sh
cargo build --release -p openncalayer -p oncl-nmhost
cargo xtask ext build   # → target/extension/
```

В `target/extension/` появятся каталоги `chromium/` и `firefox/`, а рядом — `.zip` и неподписанный `.xpi`.

### 2. Зарегистрируйте посредника

Если вы ставили программу установщиком, это уже сделано. Иначе выполните:

```sh
openncalayer nm install
```

Команда:
- копирует `nmhost` в `%LOCALAPPDATA%\OpenNCALayer\nmhost.exe` (Windows) или в каталог данных (macOS, Linux). Другой файл можно указать ключом `--relay <файл>`;
- пишет рядом `nmhost.json` с путями к каталогу данных и к `openncalayer` (у AppImage — к самому файлу `.AppImage`);
- регистрирует посредника в браузерах. В macOS и Linux — в найденных (Chrome, Chromium, Edge, Brave, Yandex Browser, Firefox). В Windows — всегда: манифесты в `%LOCALAPPDATA%\OpenNCALayer\nm\` и ключи реестра `HKCU\Software\{Google\Chrome,Chromium,Microsoft\Edge,Mozilla}\NativeMessagingHosts\io.github.arynyklas.openncalayer`.

Сертификаты команда не трогает. Проверка: `openncalayer nm status` (код 1, если чего-то не хватает). Удаление: `openncalayer nm uninstall` (каталог данных остаётся).

### 3. Установите расширение в браузер

**Chrome, Edge, Yandex Browser.** Откройте страницу расширений (`chrome://extensions`, `edge://extensions`), включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите папку `chromium` (или распакованный `.zip`). Идентификатор расширения должен быть `cmdaoegbcpdhoamhgmibpgpnlojopcal`: расширение с другим идентификатором посредник не принимает.

**Firefox** (115 и новее, в том числе ESR 115 — последний для Windows 7). Пока возможна только временная установка: `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение…» → файл `manifest.json` из папки `firefox`. После перезапуска Firefox дополнение пропадает. Постоянно ставится только подписанный XPI; неподписанный Firefox не установит.

### 4. Перезагрузите вкладки сайтов

## Что важно знать

- `nm install` берёт каталог данных так же, как `run` (с учётом `ONCL_DATA_DIR`). Если вы перенесли `openncalayer` или сменили каталог данных, повторите `nm install`.
- Повторный `nm install` заменяет посредника, не останавливая уже запущенные копии: они работают со старым файлом. В Windows `nm uninstall` не может удалить посредника, пока браузер его держит (код 1): закройте браузер и повторите.
- Программа, запущенная посредником, работает до конца сеанса. Если сертификат настроен и порт 13579 свободен, та же программа обслуживает и `wss`. Иначе она работает только для расширения, а в журнале будет предупреждение.
- Адрес сайта (origin), который видят модули, при работе через расширение берётся у браузера, а не у страницы.

### Как вернуться к оригиналу

Пока посредник установлен, сайты идут в OpenNCALayer, даже когда оригинал запущен. Чтобы вернуться к оригиналу:
1. Выполните `openncalayer nm uninstall` или отключите расширение.
2. Перезапустите браузер (или завершите программу): уже запущенные посредник и программа продолжают работать.

После отключения расширения открытые вкладки в Chromium и Firefox 128+ сами переходят на обычный `WebSocket`, но только для новых соединений и `fetch`. Соединение, которое уже было открыто через расширение, на оригинал не переключается. В Firefox 128+ при следующей отправке страница получит `error` и `close` с кодом 1006, и ждущий ответа запрос завершится ошибкой. Соединение, которое только ждёт сообщений, останется открытым, пока страница его не закроет или снова не обратится к NCALayer.

### Firefox до версии 128 (ESR 115)

В этих версиях расширение подменяет `WebSocket` и `fetch` другим способом (через Xray), поэтому есть особенности:
- после отключения, удаления, перезагрузки или обновления расширения **перезагрузите открытые вкладки**. До этого `WebSocket` и `fetch` в них выдают ошибку `TypeError: can't access dead object` — на любых сайтах, не только NCALayer;
- класс-наследник `WebSocket` не работает ни для какого адреса (подробнее — ниже).

### Firefox из snap и Flatpak (Linux)

Оба варианта не проверялись.
- **snap.** `nm install` ищет Firefox по `~/.mozilla` или `~/.config/mozilla`, а профиль snap лежит в `~/snap/firefox/`, поэтому Firefox может быть пропущен. Тогда создайте каталог `mkdir -p ~/.mozilla` и повторите `nm install`. Firefox из snap 135 и новее прочитает манифест оттуда через xdg-desktop-portal.
- **Flatpak.** Firefox из Flatpak запускает такие программы только через `xdg-native-messaging-proxy` на основной системе. OpenNCALayer его не ставит и права Flatpak не меняет: настройте это вручную.

## Отличия и ограничения расширения

- Класс-наследник `WebSocket` (`class X extends WebSocket`) для адреса NCALayer создаёт обычный `WebSocket`, а не экземпляр `X`, — во всех браузерах: такое соединение делает расширение. В Firefox ESR 115 так происходит и для любого другого адреса.
- Safari не поддерживается.
- Chrome 109 (последний для Windows 7) заявлен минимальной версией, но не проверялся.
- Соединения, которые сайт открывает из Web Worker, не подменяются: для них по-прежнему нужны `wss` и сертификат.
- Одна вкладка держит через расширение не больше 256 соединений, все вкладки профиля вместе — не больше 4096. Лишнее соединение сразу закрывается с кодом 1006, как при отказе.
- Пути native messaging для Yandex Browser и Opera не проверены. В Windows они читают ключ реестра Chrome. В Linux для Yandex Browser манифест пишется в `~/.config/yandex-browser/NativeMessagingHosts/`.
