# Аппаратные токены и удостоверение личности

Для тех, кто хочет подписывать ключом с токена или удостоверения личности РК, и для тех, кто разбирается, как это устроено. Здесь: что поддерживается, как включить, как работает PIN и что сайты могут узнать без вашего ведома.

**Статус: экспериментально, по умолчанию выключено.** OpenNCALayer умеет читать ключи и подписывать на носителях шести семейств, которые знает Kalkan. Пока ни один драйвер не проверен на настоящем носителе, только на программном эмуляторе. Там, где формат ответа выведен, а не наблюдён, в коде стоит пометка `// Unverified on hardware: …`, а у драйвера — `HARDWARE_VERIFIED = false`.

## Как включить

В окне «Настройки…» поставьте флажок «Токены и удостоверение личности (экспериментально)». В `settings.json` это `"tokens": {"enabled": true}`.

Флажок действует сразу, без перезапуска: для модулей `basics`, `commonUtils`, `Applet` и для плагинов. Ключи носителей, уже открытые в этот момент (например, у плагина до `keys_release`), после выключения не подписывают и к носителю не подключаются.

## Какие носители поддерживаются

| Хранилище | Носитель | Алгоритмы | Счётчик попыток PIN | Проверено на железе |
|---|---|---|---|---|
| `AKKaztokenStore` | Kaztoken | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | да | нет |
| `AKKZIDCardStore` | удостоверение личности РК | ГОСТ 34.10-2015 512, RSA | да | нет |
| `AKEToken72KStore` | eToken PRO 72K | ГОСТ 34.310-2004, RSA | нет | нет |
| `AKEToken5110Store` | eToken 5110 | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | нет | нет |
| `AKJaCartaStore` | JaCarta | ГОСТ 34.310-2004, RSA (под T=0 — без RSA) | нет | нет |
| `AKAKEYStore` | AKey | ГОСТ 34.310-2004, ГОСТ 34.10-2015 512, RSA | да | нет |

Для всех шести есть программный эмулятор. Семейство определяется по ATR карты (точное совпадение). У удостоверения PIN — ровно 4 ASCII-символа; PIN не из ASCII отклоняется до первой команды носителю. Облачное хранилище `ABCloudServiceStore` не поддерживается.

## Что умеет

- Показывать подключённые носители: `getActiveTokens` (commonUtils), `loadSlotList` (Applet), выбор считывателя в `browseKeyStore`, `keys_terminals` у плагинов.
- Окно хранилища (`basics` `sign`, `keys_choose`/`keys_select` плагинов, commonUtils, Applet `signXml`): строки токенов, список считывателей с кнопкой «Обновить», поле PIN. При неверном PIN пишет «Неверный PIN-код. Осталось попыток: N» (если носитель сообщает число); заблокированный PIN — отдельное сообщение.
- Читать данные удостоверения без PIN: `getPublicPartInfo` (Applet) возвращает `IIN<ИИН> <ФИО>`.
- Подписывать: CMS и CAdES, XMLDSig, «сырая» подпись плагинов. Форматы те же, что у ключей из файлов (ГОСТ — `r‖s` в порядке Kalkan, RSA — PKCS#1 v1.5). Перед отправкой странице подпись проверяется открытым ключом сертификата: неверная подпись становится ошибкой, а не битой подписью на сайте.
- Открывать токен у плагинов: `keys_open` с `terminal` берёт токен в названном считывателе с PIN от плагина, без окна.

## Чего не умеет

Запись на носитель: создание ключей (`genKeyPairAndGetPKCS10`, `generateCsr`), запись сертификата (`setX509CertToKeyStore…`, `importCertificate`), удаление ключа (`deleteEntry`), форматирование (`resetStorage`), смена PIN (`changePassword`).

Ошибка при такой записи на непроверенном железе необратима: можно перезаписать каталог ключей Kaztoken, занять запасной ключ удостоверения, отформатировать eToken. Поэтому при подключённом носителе эти вызовы отвечают общим кодом ошибки оригинала (`GENKEY_COMMON`, `SETCERT_COMMON`, `COMMON`, `CHANGEPASS_COMMON`) и не отправляют носителю ни одной команды. Без носителя коды прежние.

## Служба смарт-карт (PC/SC)

Для связи с картой нужна системная служба.

| ОС | Служба | Как подключается |
|---|---|---|
| Windows | «Смарт-карта» (SCardSvr) | `winscard.dll` (все нужные функции есть уже в Windows 7) |
| macOS | системная | `PCSC.framework` |
| Linux | `pcscd` (пакеты `pcsc-lite` и `ccid` для USB-считывателей) | `libpcsclite.so.1` открывается во время работы; без неё программа запускается как обычно |

Если службы нет (Linux без `libpcsclite.so.1` или `pcscd`, остановленная служба Windows), программа работает дальше: `getActiveTokens` отвечает `[]`, `loadSlotList` — `EMPTY_SLOT`, а окно хранилища пишет «Служба смарт-карт недоступна» с подсказкой для вашей ОС.

Считыватели опрашиваются только по запросу: при открытии окна, по кнопке «Обновить» и при каждом вызове API. Фонового опроса нет.

## PIN

- PIN хранится только в памяти программы, после использования память обнуляется. В журнал PIN не пишется.
- Каждая операция — отдельная транзакция: подключение, выбор апплета, сверка серийного номера носителя (на месте другая карта — ошибка), проверка PIN, команды, отключение.
- Операция, отправившая PIN, отключается со сбросом карты. Иначе проверка PIN осталась бы в силе для всех программ, пока карту не сбросят или не вынут. Так же закрывается сеанс AKey.
- Операции без PIN (список носителей, `getPublicPartInfo`) карту не сбрасывают, чтобы не обрывать работу других программ. `getPublicPartInfo` сначала смотрит ATR и подключается, только если это удостоверение личности.
- Если свежее подключение уже сбросил кто-то другой до первой команды, операция один раз подключается заново.
- Ключ, открытый в окне или через `keys_open`, держит PIN до конца операции (у плагинов — до `keys_release` или конца экземпляра). Если носитель отверг PIN, ни один ключ из того же вызова больше его не отправляет. Один вызов тратит не больше одной попытки.

### PIN от страницы

PIN, который вы ввели в окне хранилища, уходит носителю как есть. PIN, который прислала страница (у плагина это `keys_open` с `terminal` и паролем `text`), уходит носителю только с вашего согласия. Иначе сайт мог бы потратить попытки или заблокировать носитель без единого щелчка.

- Окно называет сайт, плагин, носитель и считыватель. Если носитель сообщает попытки (Kaztoken, удостоверение личности, AKey), показывается и число оставшихся. Их читают до отправки PIN и не тратят.
- Согласие даётся один раз на пару «сайт + считыватель» в сессии плагина. Когда осталось две попытки или меньше, окно появляется перед каждым PIN.
- После неверного PIN согласие для этого считывателя снимается: следующий PIN снова потребует окна. Сама программа PIN не повторяет.
- Отказ или закрытое окно — ответ `declined`, носителю не отправлено ничего. PIN без попыток (`blocked`) и PIN, который носитель не примет, окна не открывают и ничего не отправляют.
- PIN, который вы ввели в окне `dialog_password`, уходит без вопроса. Но если носитель его отверг, повторная отправка того же пароля — тоже только с согласием.

Applet пароль или PIN от страницы носителю не передаёт. Встроенные модули basics и commonUtils спрашивают PIN только в своём окне.

## Что сайты видят без запроса

Как и оригинальный NCALayer, программа отвечает без окна на `getActiveTokens`, `loadSlotList` и `getPublicPartInfo`. Пока поддержка включена, любой открытый сайт может:

- узнать, какие носители подключены;
- прочитать **ИИН и ФИО** владельца вставленного удостоверения личности;
- в Linux — узнать конкретный USB-носитель по серийному номеру, который `pcscd` добавляет к имени считывателя (оно видно в `loadSlotList` и `keys_terminals`).

Это одна из причин, почему поддержка выключена по умолчанию. Подписать без вашего ведома сайт всё равно не может: встроенные модули спрашивают PIN в окне хранилища, а PIN от страницы уходит носителю только после окна согласия (см. [«PIN от страницы»](#pin-от-страницы)).

## Эмулятор для тестов

Эмулятор нужен разработчикам. Он включается фичей `emulator` крейта `oncl-token` (в программе — фича `token-emulator`) и не входит ни в одну релизную сборку. Он даёт программные носители всех шести семейств: синтетические ключи из `fixtures/synthetic`, ответы на те же команды, что шлют драйверы, счётчики попыток, извлечение карты посреди операции и режим «перепутанные половины подписи».

Программа, собранная с `--features e2e-prompter,token-emulator`, при `ONCL_TOKEN_EMULATOR=<config.toml>` берёт носители из файла вместо службы смарт-карт и включает поддержку токенов. Формат файла (пути ключей — относительно каталога файла):

```toml
[[reader]]
name = "OpenNCALayer Emulated Kaztoken 0"
kind = "AKKaztokenStore"        # имя хранилища; без kind — пустой считыватель
pin = "123456"
tries = 10                      # необязательно
protocol = "T1"                 # необязательно: "T0" или "T1"
keys = [{ p12 = "fixtures/synthetic/user-gost2015-sign.p12", password = "Qwerty12" }]
# только для AKKZIDCardStore:
id_card = { iin = "123456789012", last_name = "ТЕСТОВ", first_name = "ТЕСТ", middle_name = "ТЕСТОВИЧ" }
```

Необязательны также `serial` (16 шестнадцатеричных цифр), `atr_index` и `fixed_k` (nonce ГОСТ в hex — для подписей, равных программным). Пример — `crates/openncalayer/tests/data/tokens.toml`.

Что проверяется:

- Тесты commonUtils подписывают на эмулированном Kaztoken от начала до конца: `getActiveTokens`, `getKeyInfo`, неверный и верный PIN, CAdES с цепочкой до синтетического корня, метка времени, XML. Модулю там передаются синтетические корневые сертификаты.
- Через саму программу по `wss` этот путь не проверяется: она доверяет только CA НУЦ, подложить тестовые корни нельзя, а commonUtils отклоняет ключ с другой цепочкой — для носителя так же, как для файла. По `wss` проверяются `getActiveTokens`, `loadSlotList`, `getPublicPartInfo` и подписи `basics`, которая цепочку НУЦ не требует.
- Настоящий PC/SC-бэкенд Linux проверяется в CI (job `tokens-vpcd`): `cargo xtask token-emu --config <toml> [--vpcd host:port]` отдаёт эмулированную карту виртуальному считывателю `vpcd` из vsmartcard, а `pcscd` видит её как настоящую. Это инструмент CI, он не поставляется.

## Трассировка для сообщений о проблемах

`ONCL_TOKEN_TRACE=1` в окружении программы пишет в журнал каждую команду носителю: заголовок, длину и данные команды, слово состояния и длину ответа.

- Данные команд проверки PIN и входа заменяются на `<redacted N bytes>`.
- Данные ответов не пишутся, поэтому серийный номер носителя (он приходит в ответе) в трассировку не попадает.
- Пути к файлам и имена объектов носителя (в командах выбора) в журнал попадают. Имя считывателя в Linux может содержать серийный номер USB-носителя.

Поэтому просмотрите журнал с трассировкой, прежде чем прикладывать его к сообщению.

При запуске программа пишет в журнал одну строку о токенах: включена ли поддержка и доступна ли служба смарт-карт.
